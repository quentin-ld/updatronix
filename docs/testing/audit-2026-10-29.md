# Updatronix test-system audit — 2026-10-29

**Status:** In progress. The harness audit is complete; the dimensions, environment,
risk ranking, and coverage matrix are filled in by the following steps of the
approved plan.

**Scope:** `wp-content/plugins/updatronix` (Free) and
`wp-content/plugins/updatronix-pro` (Pro), the shared test harness, the DDEV
site, and the release/merge gates.

**Method:** Read the harness and hooks; read both Playwright configs and the
fixture/license helpers; read the integration test base case; run the existing
gates on the 2026-10-29 release tree; build the case inventory in
[`inventory-2026-10-29.md`](inventory-2026-10-29.md).

**Audit rule:** a claim is only “covered” if a test asserts it and the assertion
was seen to fail against a plausible defect. A passing suite that only asserts
shapes is listed as a gap, not as coverage.

## 2. What is genuinely strong

- **One entry point.** Every developer tool goes through `bin/harness`, which
  resolves DDEV, then LocalWP, then the host. The same command works in the
  container and on the host, and the container env is forwarded deliberately.
- **Real WordPress for the oracle cases.** Integration tests use the WordPress
  test library and a separate test DB, so core behavior is not stubbed. The
  test-author skill explicitly prefers integration when a decision depends on a
  WordPress function.
- **Anti-tautology is enforced.** Infection runs on the diff, counterfactual
  catches global-function lines Infection cannot see, and the anti-pattern scan
  blocks literal assertions and unexplained skips.
- **E2E is real and isolated enough for a single site.** Playwright runs inside
  DDEV against the real admin, with a dedicated account, serial workers,
  storage state, traces on failure, and a license lifecycle that deactivates in
  teardown.
- **The license key is outside git.** `UPDATRONIX_PRO_TEST_LICENSE_KEY` is
  required by the Pro E2E helper, fails fast when missing, and is never
  committed.
- **Diff-scoped gates are fast.** Mutation and counterfactual judge the push,
  not `origin/main`; the pre-push hook reports its real cost against a measured
  budget.
- **The unit/integration split is healthy.** 470 Pro unit and 94 Pro
  integration cases; 315 Free unit and 196 Free integration cases. The split is
  not a thin unit suite standing in for real WordPress behavior.

## 4. What the harness should become

- **`bin/harness testbook`**: `list`, `run`, `reset`, `smoke`, `report`.
- **Two sites**: a dedicated single-site DDEV project and a dedicated multisite
  DDEV project; the working site is never mutated by the book.
- **One catalog**: `tests/testbook/dimensions.yaml`, `cases.yaml`,
  `invariants.yaml`, `fixtures.yaml`; `docs/testing/test-book.md` generated.
- **Three oracles per case**: what the human sees (Playwright), what WordPress
  did (disk/DB/log/pass), and what was sent (mail).
- **Fast vs full**: pre-push runs `testbook smoke`; release/merge to main runs
  `testbook run --tag @release-only` (or the full book).
- **Freshness**: a setting key, route, screen, or feature flag without a mapped
  case fails the book check.

**Values policy.** Every dimension declares its full domain. Enumerations list
every value. Integer ranges name the full range and a boundary/equivalence point
set; the pairwise generator uses the points, because a clamp tested at 0, 1,
max-1 and max is the same decision as testing every integer. External value
spaces (WordPress versions, package failures) are marked `open` and exercised
through named fixtures. This is the answer to “exhaustive”: every dimension and
every value is listed, while the runnable matrix is pairwise plus named
high-risk triples, not the impossible Cartesian product.

The catalog includes the dimensions that were previously invisible in the test
plan: the ten Shield booleans/enums, the Version Lock detection matrix, the pass
planning/gate states, the Flow chain shapes and predecessor states, the license
statuses, White Label file/color boundaries, native constants, roles, multisite
scopes, and the update package/email outcomes.

## 8. Risk ranking

Ranked by the owner's order: **update breakage first**, then data loss,

priority for the test book, not a claim that a lower risk is safe.

**Why R-01 is first.** It is the only failure that leaves a site unpatched or
broken while the admin believes it is protected. A blocked eligible update is a
security defect; a duplicated update can corrupt a plugin directory; a
half-applied update is a white screen waiting to happen. Every other risk is
either a consequence of this one (R-02, R-07, R-09) or a narrower blast radius.

**Why data loss is second.** The queue table is dropped by design. A missing
backup, an uninstall with the wrong opt-in, or a retention bug is unrecoverable
from the plugin; the log is only history, not a backup.

## 9. Top invariants the book must enforce

These are the seed for `tests/testbook/invariants.yaml`; every combination runs
them, and a failure names the dimension values that produced it.

- **I-01** An eligible native automatic update installs exactly once.
- **I-02** A non-eligible item is never installed; the reason is recorded once.
- **I-03** One native email per item; one item row and one pass summary per pass.
- **I-04** A failed/partial update is never reported as success in the log, UI, or email.
- **I-05** A manual update is blocked only when the manual switch is on; WP-CLI remains available.
- **I-06** Version Lock never rewrites the stored `auto_update_*` option and never blocks the pass's own write.
- **I-07** Shield off disables Shield and Version Lock; it never silently blocks a native update.
- **I-08** No fatal/500 in any admin, native, cron, REST, or network path for any combination.
- **I-09** Multisite: the pass is main-site only; network schedule/logs/site deletion are correct; a subsite admin cannot reach Pro routes.
- **I-10** The license fails closed: no Pro route or execution without an active license, and the recovery paths work.
- **I-11** Data is deleted only when the explicit setting allows it; the queue drop is backup-gated and documented.
- **I-12** Every control is keyboard reachable, focus-visible, labelled, and free of horizontal overflow at 390/760.

## 11. Gaps and flake sources

### Blocking gaps

- **No live multisite browser path.** The network contract is integration-only
  (H-01, E-01).
- **No native-update/email/disk oracle.** E2E cannot prove an update installed,
  sent one email, wrote one row, and wrote one pass summary (H-02, H-06, R-01/R-02).
- **No combination runner.** The 88 dimensions exist, but no pairwise/triple
  matrix exercises their interactions (H-03).
- **No recoverable E2E reset.** A killed run leaves options/logs; there is no
  DB snapshot or filesystem restore (H-04, E-06).
- **No community fixture base or clock/cron control.** Real-world updates and
  time-dependent states are not forced (H-05, H-07, E-04).
- **Pre-release does not run the full book.** E2E, JS, multisite, mutation and
  counterfactual are outside `.githooks/pre-release` (H-09).

### Flake sources

| Source | Finding | Effect |
|---|---|---|
| Shared E2E site, option-only reset | H-04, E-06 | Killed runs leave state; suites are order-dependent. |
| Live license API | H-04 | Activation can throttle or fail; Pro E2E needs the real key. |
| Real wall clock / WP-Cron | H-07, E-04 | Hold, next-eligible, retries, stale passes cannot be forced. |
| Host/DDEV split | E-02 | Unit/integration on host PHP 8.4.27; browser in DDEV PHP 8.4. |
| Environment-specific Git markers | H-16 | A spec can pass because the workspace is a checkout. |
| Full multisite test mode | H-10 | Two single-site capability tests fail without a Super Admin. |
| Persistent admin users | E-08 | Role tests can run over-privileged. |
| Selector / copy drift | H-13 | Role/label selectors and docs lag the UI. |

## 12. Proposed case-ID schema

- **Case ID:** `TB-<GROUP>-<NNN>` — stable, never reused. Groups: `SET`,
  `SCHED`, `AUTO`, `LOG`, `EXPORT`, `HEALTH`, `UI`, `SHIELD`, `VLOCK`, `PASS`,
  `PLAN`, `FLOW`, `LIC`, `WL`, `UPDATE`, `ENV`, `ROLE`, `MS`.
- **Combination ID:** `COMBO-<NNN>` for a pairwise or high-risk-triple row, with
  `dimensions:` naming each `id=value` pair.
- **Invariant ID:** `INV-<NN>` for a rule that runs after every case.
- **Tags:** `@free`, `@pro`, `@multisite`, `@license`, `@pass`, `@flow`,
  `@version-lock`, `@schedule`, `@logger`, `@export`, `@a11y`, `@combo`,
  `@invariant`, `@smoke`, `@release-only`.
- **Required case fields:** `id`, `title`, `owner`, `risk`, `tags`,
  `dimensions`, `preconditions`, `steps`, `assertions`, `oracle`, `cleanup`,
  `automation`.
- **Retirement:** a retired case keeps its ID with `status: retired` and a
  `replaced_by` field; a new case takes a new number.
